# KAN-54 카드(회의비) 내역 엑셀 가져오기 설계

작성일: 2026-09-21 · 상태: 리뷰 요청 · 작성: 한강섭

기준: 기획서 3.2 [유즈케이스 2], 랩실이 실제로 쓰는 기록 파일 사본(2026-09-21 수령). 팀 결정에 따라 구글 API 연동 대신 **엑셀 파일 업로드**로 구현한다. 이 문서는 규칙만 정한다. 코드·DB 는 바꾸지 않았다.

> 실제 파일에는 참석자 이름과 외부 인원의 소속·직함이 들어 있다. 저장소가 공개이므로 **파일은 커밋하지 않고**, 이 문서에는 집계 수치와 가상 예시만 적는다.

## 요약

- **원본 양식을 바꾸지 않는다.** 지금 쓰는 월별 시트("회의록 인원") 그대로 받는다.
- 사용자는 구글 시트에서 `.xlsx` 로 내려받아 올린다. 서버는 이름이 `YYYY년 M월` 꼴인 시트를 모두 읽는다.
- **파일에 들어 있는 달은 파일 내용으로 통째로 맞추고, 파일에 없는 달은 건드리지 않는다.**
- 올리기 전에 미리보기로 달별 추가·사라짐 건수와 문제 행을 보여 주고, 확인하면 반영한다.
- 구글 API 인증·조회·주기 동기화(KAN-55, 56, 59 의 스케줄러)는 하지 않는다. 파서는 "시트 이름 + 셀 격자"만 받게 만들어, 나중에 구글 시트를 직접 읽게 되더라도 읽는 부분만 바꾸면 된다.

## 1. 원본 파일 분석

사본 전체(시트 88개)를 전수 조사했다.

| 항목 | 값 |
| --- | --- |
| 연도가 있는 월 시트 | 74개 — 2020년 8월 ~ 2026년 9월, 빠진 달 없음 |
| 연도가 없는 월 시트 | 12개 — `7월` … `8월`. 순서로 보아 2019~2020년 기록 |
| 양식 복사용 시트 | 2개 — `복사용 시트`, `복사용시트2` |
| 사용 기록 | 약 2,550건, 한 달 9~56건 |
| 시트 크기 | 최대 66행, 파일 605KB |

기획서의 "대상 카드, 회의/초과, 인원"이 이 파일의 "과제명, 점심·저녁/초과, 인원"에 그대로 대응한다. 기획서가 말한 공유 문서가 이 시트다.

### 1.1 시트 한 장의 모양

| 열 | 1행 머리글 | 내용 | 가져오기 |
| --- | --- | --- | --- |
| A | 날짜 (또는 아무 값) | 그날 **첫 행에만** 일(1~31). 같은 날 두 번째 건부터는 비워 둔다 | 사용일 |
| B | `과제명 or 출장` (옛 시트는 `과제명`) | 결제한 과제 | 카드 |
| C | `인원` | 이름을 쉼표로 나열 | 참석자 |
| D | `점심 or 저녁` | 점심 / 저녁 / 초과 | 구분 |
| E, F | `메뉴`, `회의시간` (2022~2023 일부 시트) | | 읽지 않음 |
| G~K | 머리글 없음 | 참고용 명단 — 이름·소속·직함·메모. 사용 기록이 아니다 | **읽지 않음** |

가상 예시:

| A | B | C | D | 해석 |
| --- | --- | --- | --- | --- |
| 1 | BRL | 홍길동, 김철수, 이영희 | 저녁 | 9월 1일 |
| | 과제A | 박민수, 최지우 | 점심 | 9월 1일 (윗행 이어받음) |
| 2 | | | 점심 | 사용 아님 — 양식에 미리 채워 둔 구분 |
| 3 | BRL | 홍길동 | 초과 | 9월 3일 |

### 1.2 믿으면 안 되는 것

- **A1 칸.** 다른 달 날짜를 복사해 둔 채인 시트가 있다(2026년 5·7·8월 시트의 A1 이 모두 4월 1일). 비었거나 `ㅅ`, `8` 인 시트도 있다. → **연월은 시트 이름에서 읽는다.**
- **시트 이름 표기.** `2026년 9월` 꼴 25개, `2024 7월` 꼴 48개에 `2026년2월`, `2024 01월` 이 섞여 있다. → 정규식 하나로 받는다(§3.3).
- **시트 순서.** 섞여 있다(`2024 7월` 이 `2024년 10월` 뒤). → 순서에 의미를 두지 않는다.

### 1.3 행 단위 예외

| 경우 | 건수 | 처리 |
| --- | --- | --- |
| 구분(D)만 있고 과제·인원 없음 — 양식에 미리 채워 둔 칸 | 61행 | 사용 아님. 조용히 무시 |
| 과제·인원은 있는데 구분(D) 없음 | 318건 (12%) | 가져온다. 구분 없이 표시 |
| 과제(B)만 있고 인원(C) 없음 | 12건 | 가져온다. 참석자 0명, 경고 |
| 인원(C)만 있고 과제(B) 없음 | 5건 | 카드를 알 수 없어 건너뛴다. 오류로 보고 |
| A 에 `15(광복절)` 같은 메모 | 1건 | 앞의 숫자만 읽는다 |
| 같은 일이 두 행 연속으로 적힘 | 7건 | 문제없음 |
| 그 달에 없는 날짜(9월 31일 등) | 0건 | 건너뛴다. 오류로 보고 |

**구분(D)** — `점심` 882, `저녁` 884, `초과` 454 가 97%. 나머지 18가지 표기는 `식대` 29, `저녁(초과근무)` 28, `출장` 6, `회의` 3 과 줄임말(`점/저`), 오타(`져녁`, `점ㅅ미`) 등이다.

**과제(B)** — 상위 15개 표기가 90%. 같은 과제를 `OO_과제명` / `OO과제명` / `OO 과제명` / `OO-과제명` 처럼 여러 모양으로 적는다. `BRL/과제A` 처럼 두 과제를 함께 적은 행이 5건.

**인원(C)** — 쉼표 2,334건, 빗금(`/`) 14건, 띄어쓰기로만 구분 41건, 괄호 메모 23건, `+` 2건, `외부 2명` 처럼 수만 적은 것 1건. 한 건에 1~20명이고 3~6명이 가장 많다.

## 2. 사용 흐름

1. 평소처럼 구글 시트에 적는다. **바뀌는 것 없음.**
2. 편집 등급 사용자가 구글 시트에서 `파일 → 다운로드 → Microsoft Excel(.xlsx)` 로 받는다.
3. "카드 내역 가져오기" 화면에 올리면 **미리보기**가 뜬다 — 달별 추가 / 사라짐 / 그대로 건수, 문제 행 목록(`2026년 9월 시트 14행 — 과제명이 비어 있어 건너뜁니다`).
4. "반영"을 누르면 저장되고 달력의 카드/경비 카테고리에 나타난다.

올리는 주기는 정하지 않는다. 파일 전체를 매번 올려도 바뀐 것이 없으면 "변경 없음"이다.

## 3. 반영 규칙

### 3.1 달 단위 교체

**파일에 들어 있는 달은 그 파일이 정답이다.**

| 경우 | 처리 |
| --- | --- |
| 파일에 새로 생긴 행 | 추가 |
| 그대로인 행 | 그대로 (일정 id 유지) |
| 파일에서 사라진 행 | 비활성 + 연결 일정 삭제 (database-design §6 제안과 같다). 다시 나타나면 재활성 |
| 파일에 없는 달 | 손대지 않음 — 올해 시트만 남긴 파일을 올려도 작년 기록은 그대로 |

**행 번호가 아니라 내용으로 식별한다.** 원본에는 행 id 가 없다. 행 번호로 식별하면 한 줄을 중간에 끼워 넣었을 때 그 아래가 전부 "바뀜"이 되어 미리보기가 쓸모없어진다.

- `source_document_id` = `ledger:2026-09` (달)
- `source_record_id` = SHA-256(`일|카드|인원 원문|구분` — 앞뒤 공백 제거, 연속 공백 하나로) + `#순번`

순번은 같은 날 완전히 같은 행이 두 번 있을 때를 위한 것이다. 사본에서는 0건이지만 막아 둔다.

내용이 바뀐 행(참석자 한 명 추가 등)은 "사라짐 1 + 추가 1"로 센다. 카드 일정은 사람이 고칠 수 없는 읽기 전용이라 id 가 바뀌어도 잃는 것이 없다.

### 3.2 전부 아니면 전무, 단 문제 행은 빼고

- **파일 오류** — `.xlsx` 가 아님, 크기 초과, 읽을 수 있는 월 시트가 하나도 없음, 같은 연월 시트가 둘, 머리글을 못 찾음 → 400. **아무것도 바꾸지 않는다.**
- **행 오류** — 그 행만 건너뛰고 나머지는 반영한다(`sync_log.status = PARTIAL`). 건너뛴 행은 달 단위 교체에서 "없는 행"이 되므로 **전에 들어가 있던 행이라면 달력에서 내려간다.** 미리보기를 먼저 보여 주는 이유다.
- 반영은 한 트랜잭션. 중간에 실패하면 전부 되돌리고 실패 이력만 남긴다(이력은 별도 트랜잭션, database-design §4 sync_log 와 같다).
- 업로드는 한 번에 하나만 처리한다. 서버가 한 대라 애플리케이션 락으로 충분하고, 뚫리더라도 `uq_card_source` 가 중복을 막는다.

### 3.3 시트와 열 찾기

- 이름이 `^(\d{4})\s*년?\s*0?(\d{1,2})\s*월$` 이면 월 시트.
- 그 밖(`복사용 시트`, 연도 없는 `7월`)은 건너뛰고 "건너뛴 시트"로 알린다. 연도 없는 12개는 2019~2020년 기록으로 보이지만 **시트 순서로 연도를 짐작하지 않는다.** 틀리게 짐작하면 1년 어긋난 기록이 달력에 올라간다.
- 열은 1행에서 찾는다 — `과제` 가 든 칸이 카드, `인원` 이 든 칸이 참석자, `점심` 또는 `저녁` 이 든 칸이 구분. 날짜는 A 열. 앞에 열이 하나 끼어도 따라간다.

## 4. 행 해석 규칙 (KAN-57)

**사용 기록인지** — 과제(B)나 인원(C) 중 하나라도 있으면 사용 기록이다. 구분(D)만 있는 행은 양식 칸이다.

**일(A)** — 숫자로 시작하면 그 숫자(`15(광복절)` → 15). 비었으면 윗행의 일을 이어받는다. 시트 첫 기록부터 일이 없거나, 그 달에 없는 날이면 오류.

**카드(B)** — 앞뒤 공백을 떼고 연속 공백을 하나로. **표기 통일(`OO_과제명` = `OO 과제명`)은 하지 않는다.** 추측으로 합치면 틀렸을 때 되돌릴 방법이 없다. 과제별 모아 보기가 필요해지면 별칭 표를 둔다(§8).

**구분(D)** — 원문을 `purpose` 에 그대로 둔다(달력 표시용). 분류는 `usage_type` 에:

| usage_type | 규칙 | 기획서 |
| --- | --- | --- |
| `OVERTIME` | `초과` 가 들어 있음 (`저녁(초과근무)` 포함) | 초과 |
| `LUNCH` | `점심` 만 | 회의 |
| `DINNER` | `저녁` 만 (오타 `져녁` 포함) | 회의 |
| `NONE` | 비었음 | |
| `OTHER` | 그 밖 (`식대`, `출장`, `점심,저녁`, 다른 오타) | |

**인원(C)** — 원문은 `participant_names_raw` 에 그대로 둔다. 참석자 목록은 다음 순서로 만든다.

1. `,` `/` `+` 줄바꿈으로 나눈다.
2. 괄호 안 메모와 끝의 `.` `` ` `` `\` `!` 를 뗀다.
3. 띄어쓰기로만 이어 적은 이름(`홍길동 김철수 이영희` — 조각마다 한글 2~4자)은 띄어쓰기로 나눈다.
4. `외부 2명`, `19명` 처럼 수를 적은 조각은 이름이 아니므로 뺀다.
5. 100자를 넘는 조각은 자른다(`event_participant.display_name`).

위 과정에서 무엇이든 빠지거나 바뀌었으면 **상세 팝업 메모에 원문을 남긴다.** 해석이 틀려도 정보는 잃지 않는다. 이름으로 `member` 를 자동 연결하지 않는다(database-design §5.1 방침).

## 5. 달력 표시

| 응답 필드 | 값 | 예 |
| --- | --- | --- |
| `title` | 카드(B) | `BRL` |
| `detail` | 구분(D) 원문. 비었으면 `null` | `저녁` |
| `participants` | §4 참석자 목록 | `홍길동, 김철수, 이영희` |
| `memo` | 원문과 목록이 다를 때만 원문 | |

달력 칩은 계약 §6.2 의 카드 형식 `title: detail` 그대로 `BRL: 저녁`, 구분이 없으면 `BRL`. 상세 팝업에 "참석 인원 홍길동, 김철수, 이영희 · 총 3명"이 뜬다(이미 구현됨).

## 6. 변경 사항

### 6.1 DB — `V1.1.0.003`

- `event.source` 의 `GOOGLE_SYNC` 를 `CARD_IMPORT` 로 바꾼다(`ck_event_source` 재생성). 구글 연동을 하지 않으니 이름이 거짓말이 되고, 카드 데이터가 0건인 지금이 가장 싸게 바꿀 때다.
- `sync_log.deactivated_count` 를 더한다 — 업로드가 비활성으로 돌린 건수.
- `card_expense` 는 그대로 쓴다(`used_on`, `card_name`, `purpose`, `usage_type`, `participant_names_raw`, `active`, `last_seen_at`, 원본 복합 UNIQUE).
- 올린 파일은 저장하지 않는다. `sync_log.source_document_id` 에 파일 이름만 남긴다.

### 6.2 API

**`POST /api/card-expenses/imports`** — `multipart/form-data`, 필드 `file`, 쿼리 `dryRun` (기본 `false`)

```json
{
  "data": {
    "dryRun": true,
    "fileName": "회의록 인원.xlsx",
    "months": [
      { "month": "2026-09", "added": 2, "removed": 0, "unchanged": 18 }
    ],
    "skippedSheets": [
      { "sheet": "7월", "reason": "YEAR_MISSING" }
    ],
    "problems": [
      {
        "sheet": "2026년 9월", "row": 14, "level": "ERROR",
        "code": "CARD_MISSING", "message": "과제명이 비어 있어 건너뜁니다."
      }
    ],
    "totals": { "added": 2, "removed": 0, "unchanged": 2519, "skippedRows": 5 }
  }
}
```

- 편집 등급만. 조회 등급은 403 (기존 인터셉터와 카드 차단 규칙).
- 파일 오류는 400, 5MB 초과는 413. 사본은 605KB 다.
- `dryRun=true` 는 아무것도 저장하지 않는다. 이력도 남기지 않는다.
- 프론트는 미리보기 후 **같은 파일로 한 번 더** 부른다. 서버에 임시 파일을 두지 않기 위해서다. 사이에 누가 먼저 올렸다면 결과가 미리보기와 다를 수 있지만, 결과 화면이 실제 숫자를 보여 준다.

**`GET /api/card-expenses/imports?limit=20`** — 최근 업로드 이력과 문제 행 (KAN-60).

### 6.3 프론트 (KAN-61)

- 편집 등급 메뉴에 "카드 내역" 화면: 파일 선택 → 미리보기 표 → 반영 → 결과, 아래에 최근 이력. 사라지는 건이 있는 달은 눈에 띄게 표시한다.
- `EventSource` 의 `GOOGLE_SYNC` → `CARD_IMPORT`. 상세 팝업 안내를 "엑셀 원본을 고친 뒤 다시 올려 주세요"로, 카드 `detail` 이름표를 "구분"으로.
- 달력 칩·카테고리 필터·상세 팝업은 이미 있다.

## 7. 보안과 개인정보

- 참석자 이름은 개인정보다. 카드 데이터는 편집 등급만 본다 — 조회 등급은 목록·단건·카테고리에서 이미 빠진다(KAN-35).
- **필요한 열(A~D)만 읽는다.** G 열 이후의 명단(외부 인원의 소속·직함·메모)은 읽지도 저장하지도 않는다.
- 파일은 메모리에서 읽고 버린다. 오류 메시지와 로그에는 참석자 이름을 넣지 않는다 — 시트·행·사유 코드만.
- `.xlsx` 만 받는다. `.xls`, 매크로 파일(`.xlsm`)은 거부한다. 수식은 계산하지 않고 저장된 값만 읽는다. POI 의 압축 폭탄 방어 기본값을 끄지 않는다.
- **실제 파일은 저장소에 넣지 않는다.** 테스트는 가상 이름으로 테스트 코드 안에서 POI 로 워크북을 만들어 쓴다. `.gitignore` 에 `*.xlsx` 를 더한다.

## 10. 확인이 필요한 것

1. **과제명(B)을 카드로 봐도 되는가.** 기획서는 제목에 카드 종류(`[법인카드 A]`)를 쓰자고 했지만 파일에는 카드 열이 없다. 과제마다 연구비 카드가 따로라 과제명이 곧 카드라고 보고 `BRL: 저녁` 으로 제안한다.
2. **과거 기록을 어디까지 올릴 것인가.** 파일을 그대로 올리면 연도 있는 74개월(2020년 8월~)이 모두 들어간다. 달력은 보는 달만 읽으므로 부담은 없다. 올해분만 원하면 옛 시트를 지운 사본을 올리면 된다.
3. **구분(D)이 빈 12%.** 그대로 가져와 구분 없이 표시하자고 제안한다. 오류로 건너뛰면 318건이 빠진다.
4. **연도 없는 옛 시트 12개**를 건너뛰어도 되는가. 필요하면 시트 이름에 연도를 붙여 올리면 된다.
