# KAN-56 시트 이름 테스트 준비

## 2026-09-27 구현 현황

아래는 준비 당시 기록이다. 현재 DESIGN_CASES 12개는 LedgerSheetSelectorTests의 실행 가능한 분류 테스트로 연결했다. 중복 월·모두 제외·머리글 오류·빈 월·순서와 원래 행 번호 보존도 검증한다. 0월과 13월은 유효한 YearMonth가 아니므로 INVALID_MONTH로 거부한다.

머지된 §3.3 정규식을 그대로 구현했으므로 `2026년 009월`과 `20269월`은 2026-09로, `0000년 9월`은 0000-09로 읽는다. 앞뒤 공백은 제거하지 않아 해당 이름은 NOT_MONTH_SHEET다. 아래 PROPOSED_CASES의 나머지 강화 정책은 적용하지 않았다. 이 차이는 회귀 테스트로 명시했고 정책 변경 시 설계와 테스트를 함께 바꿔야 한다.

이 문서는 KAN-54 리뷰 중인 설계에 대한 **예상 결과 목록**이다. 월 분류기는 아직 구현하지 않았다. Java 픽스처 `SheetNameCases`의 DESIGN_CASES는 현 설계 기준, PROPOSED_CASES는 추가 합의가 필요한 추천값이다. reason 코드는 YEAR_MISSING을 제외하면 이 문서에서 제안한 이름이다.

## 현 설계 기준

| 입력 | 예상 결과 | 이유 |
| --- | --- | --- |
| `2026년 9월` | 2026-09 | 기본 형식 |
| `2024 7월` | 2024-07 | 년 생략, 공백 구분 |
| `2026년2월` | 2026-02 | 공백 없음 |
| `2024 01월` | 2024-01 | 월의 앞자리 0 허용 |
| `2026년 12월` | 2026-12 | 월 상한 |
| `2026  9월` | 2026-09 | 구분 공백 여러 개 |
| `7월`, `08월` | SKIP / YEAR_MISSING | 연도를 시트 순서나 A1로 추측하지 않음 |
| `복사용 시트`, `복사용시트2`, `메모` | SKIP / NOT_MONTH_SHEET | 월 시트 아님 |
| `2026년 9월 사본` | SKIP / NOT_MONTH_SHEET | 전체 이름 일치 조건 위반 |

SKIP은 응답의 skippedSheets에 이름과 사유가 남는다는 뜻이다. 파일의 모든 시트가 SKIP이면 읽을 월이 없으므로 파일 오류다. 화면에서 건너뛴 시트를 사용자에게 보여줘야 한다.

## 추가 합의가 필요한 추천값

| 입력 | 추천 결과 | 확인할 점 |
| --- | --- | --- |
| ` 2026년 9월 ` | 앞뒤 공백 제거 후 2026-09 | 원래 이름은 사용자 안내용으로 보존 |
| `2026년 0월`, `2026년 13월` | ERROR / INVALID_MONTH | 정규식 일치만으로 유효 월이 되지 않음 |
| `0000년 9월` | ERROR / INVALID_YEAR | YearMonth는 0년을 허용하지만 업무 범위와 다름 |
| `2026년 009월` | ERROR / INVALID_MONTH_FORMAT | 초안의 `0?` + 1~2자리 월은 세 자리까지 허용할 수 있음 |
| `20269월` | ERROR / INVALID_MONTH_FORMAT | 초안은 년과 공백을 모두 생략할 수 있어 모호한 표기까지 허용함 |

월처럼 보이지만 잘못된 이름은 조용히 SKIP하기보다 파일 오류로 알리는 방안을 추천한다. 실제 구현 전 팀원과 합의해야 하며, 아직 확정된 거부 정책이 아니다. 승인되면 KAN-54 정규식·에러 정의와 픽스처를 함께 맞춘다.

## 여러 시트가 있는 파일

| 시트 이름 목록 | 예상 결과 |
| --- | --- |
| `2026년 9월`, `2026 09월` | 같은 2026-09이므로 파일 오류: DUPLICATE_MONTH(코드명 제안) |
| `2026년 9월`, `2026년 8월` | 두 월 모두 읽기. 시트 순서로 연월을 바꾸지 않음 |
| `2026년 9월`, `7월`, `복사용 시트` | 2026-09 한 월과 건너뛴 시트 두 개 |
| `7월`, `복사용 시트` | 읽을 월이 없어 파일 오류: NO_MONTH_SHEETS(코드명 제안) |
| `2026년 9월`, `2026년 13월` | 잘못된 월 정책 합의 후 파일 전체 ERROR 여부 확정 |

현재 ExcelLedgerReader는 이 모든 이름을 원문 그대로 반환한다. 정상 월·중복 월 판정, SKIP 사유 및 오류 발생은 후속 분류기 테스트에서 검증할 사항이다.

## 실행 가능한 테스트와 아직 실행하지 않는 검증

`ExcelLedgerReaderTests.preservesSheetNamesForTheFutureClassifier`는 가상 워크북으로 위 18개 이름이 읽기 계층을 통과하며 원문이 유지되는지만 검증한다. 테스트 통과는 **월 판별 구현 완료를 의미하지 않는다**.

분류기 구현 후 DESIGN_CASES를 @MethodSource로 공급해 outcome·month·reason을 비교하고, 다중 시트 표의 파일 단위 검증을 추가한다. PROPOSED_CASES는 합의 전까지 자동 합격 기준에 포함하지 않는다. 빈 시트·머리글 오류·행 오류는 이름 판별과 별도 테스트로 다룬다.
