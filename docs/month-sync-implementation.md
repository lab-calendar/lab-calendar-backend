# KAN-58 현재 구현과 후속 연결

2026-09-29 리뷰 반영: 카드 카테고리는 반영 요청당 한 번만 조회하며 미리보기에는 조회하지 않는다. 미리보기 전용 TransactionTemplate에 readOnly=true를 지정했다. 실패 이력에도 원래 months의 문제 위치·코드·등급과 오류 행 수를 보존한다. JDBC 예외 원문은 여전히 기록하지 않는다. 재활성화를 added로 세는 선택은 팀 리뷰에서 승인됐다.

테스트 DB 주소는 MIGRATION_TEST_URL을 따라 H2와 MySQL에서 같은 동기화 테스트를 실행한다. 실패 주입용 CHECK 삭제 문법도 DB에 맞춘다.

KAN-57 `LedgerRowParser.ParsedMonth`를 입력으로 받는 내부 `LedgerSyncService`를 구현했다. 업로드 엔드포인트는 없다. `preview(months)`는 DB 차이를 읽고 `apply(fileName, months)`는 정상 월을 반영한다. KAN-57 리뷰 후 입력 구조·오류 정책을 다시 맞춰야 한다.

## 반영 규칙

- JSON 문자열 배열 `[일, 카드, 인원 원문, 구분]`의 공백을 정규화하고 UTF-8 SHA-256을 만든다. 일은 앞자리 0 없는 십진 문자열, 중복 순번은 1부터 `#1`로 붙인다. 월 키는 `ledger:YYYY-MM`이다.
- 같은 원본 키가 활성 상태면 내역·일정·참석자 ID와 내용을 유지하며 last_seen_at만 갱신한다. 정규화 후 같은 내용이면 최초 저장 원문을 유지한다.
- 없는 키는 내역과 종일 일정 및 순서가 있는 자유 입력 참석자를 생성한다. member 연결은 만들지 않는다.
- 파일에서 사라진 활성 내역은 비활성화하고 일정을 삭제한다. FK cascade로 일정 참석자도 삭제한다.
- 비활성 키 재등장은 **added로 집계**하고 기존 expense ID를 재사용한다. 일정은 새로 생성한다. 이 집계 선택은 리뷰 확인 사항이다.
- BLOCKED 월은 DB를 읽어 변경 대상으로 만들지도 않는다. 파일에 없는 달도 손대지 않는다. 모든 월 BLOCKED는 NO_APPLICABLE_MONTHS로 거부한다.
- 미리보기는 업무 데이터와 이력 모두 쓰지 않는다. 반영은 한 트랜잭션이며 성공/PARTIAL 이력도 함께 커밋한다. 중간 실패는 업무 트랜잭션을 롤백한 뒤 별도 트랜잭션으로 FAILED 이력을 남긴다. 내부 SQL 예외·셀 내용은 예외 원인이나 실패 메시지로 전달하지 않는다.
- sync_log에 deactivated_count를 추가한다. created_count는 재활성화 포함 added, processed_count는 added+unchanged, updated_count는 0, skipped_count는 오류 행 수다. 문제 기록에는 위치·코드와 WARNING/ERROR 등급만 저장한다.

## 호환성과 제한

- 현재 웹·DB 계약과 맞추기 위해 source는 **GOOGLE_SYNC를 유지**한다. CARD_IMPORT 전환은 enum·제약·기존 데이터 변환·프론트 어댑터를 함께 변경하는 별도 후속 변경으로 남겼다. 이번 마이그레이션 1.1.0.003은 이력의 제거 건수만 추가한다. 후속 마이그레이션 번호는 다시 배정해야 한다.
- 구분이 빈 카드 일정의 API detail은 null로 반환한다. 기존 일정 조회의 EDITOR 공개/VIEWER 비공개와 직접 수정·삭제 금지 정책을 재사용한다.
- MySQL DATE에 저장할 수 없는 1000년 미만·10000년 이상은 쓰기 전에 거부한다. KAN-56 정규식의 연도 0000 허용과의 차이는 리뷰에서 함께 정리해야 한다.
- 단일 JVM의 공용 ReentrantLock을 획득한 뒤 트랜잭션을 시작하고 실제 커밋/롤백 이후 해제한다. 외부 트랜잭션에서 호출하면 거부하여 JPA 캐시와 DB 락을 가진 채 이 서비스를 호출하는 것을 막는다. JDBC로 같은 Spring 트랜잭션 매니저를 사용한다.
- 다중 서버에서는 이 락만으로 안전하지 않다. 여러 인스턴스에서 업로드를 열기 전에 DB 기반 직렬화가 필요하다.
- **KAN-59의 토큰 검증은 아직 없다.** 미리보기 지문 계산과 차이 계산, 반영 시 토큰/DB 버전 검증을 이 잠금 범위 내부에 통합해야 한다. 컨트롤러에서 먼저 검증하고 나중에 apply를 호출하면 경합이 생긴다. 내부 서비스에 직접 연결한 HTTP 반영 API를 먼저 노출하지 않는다.
- API 인증·실패 응답 매핑은 KAN-59, 이력 조회는 KAN-60 범위다. 파일은 저장하지 않고 이력에는 경로와 제어문자를 제거하고 길이를 제한한 파일 이름만 남긴다.

## 검증

LedgerSyncServiceTests는 별도 H2 MySQL 모드 DB에서 준비된 12개 사례를 실제 반영한다. 추가 테스트는 미리보기 무변경, 멱등성과 ID 유지, 재활성화, 비활성 행까지 포함한 오류 월 보존, 늦은 실패의 삭제/생성 롤백과 실패 이력, JSON 키 경계, 외부 트랜잭션 거부, 커밋 전 경쟁 요청, 생성된 일정의 권한과 표시를 확인한다.

실제 MySQL과 배포 환경의 동시성 검증은 수행하지 않았다. KAN-56·57 머지 후 최신 develop 반영 및 전체 테스트 재실행이 필요하다.
