# KAN-57 카드 내역 행 해석

KAN-54 §4에 따라 `LedgerRowParser`가 KAN-56의 `Selection` 또는 `MonthSheet`를 해석한다. 원시 읽기 → 시트·머리글 검증 → 행 해석 순서다. 실제 파일 대신 코드에서 만든 가상 워크북으로 검증한다.

## 결과

- `ParsedMonth`는 시트 이름, 연월, 정상 해석된 `entries`, `problems`를 보존한다.
- 오류가 하나라도 있으면 `status()`는 BLOCKED, `applicableEntries()`는 빈 목록이다. 정상 해석된 행은 진단용으로 남지만 **entries를 직접 DB에 반영하면 안 된다**. KAN-58은 상태를 먼저 확인하고 BLOCKED 월의 기존 내역·일정을 모두 보존해야 한다.
- WARNING만 있거나 유효한 빈 월이면 READY다. 빈 READY와 오류로 행이 없는 BLOCKED는 다르다.
- 문제에는 시트·원래 행 번호·등급·코드만 있고 셀 내용이나 참석자 이름은 넣지 않는다. `errorRowCount()`는 여러 오류가 있는 행도 한 번만 센다.
- Entry는 사용일·과제명·구분 원문·분류·참석자 원문·이름 목록·총 인원수·원문 보존 메모를 제공한다. 리스트는 불변이다.

## 구현상 보수적 처리와 리뷰 사항

- 잘못된 날짜가 양식 행에 있어도 INVALID_DATE로 월을 보류한다. 그 뒤 사용 행이 잘못된 날짜를 이어받는 것을 막는다.
- 정규화한 과제명이 DB 한도 100자를 넘으면 CARD_TOO_LONG으로 월을 보류한다. 과제명을 임의로 자르거나 합치지 않는다.
- 숫자로 시작하는 날짜는 설계대로 앞의 정수만 사용한다. 예를 들어 `15일`은 15일이다. 엑셀 전체 날짜·소수 표기를 별도 날짜 형식으로 추론하지 않는다.
- 참석자 중복 이름은 유지한다. 임의 직함 제거·구성원 자동 연결은 하지 않는다. 괄호 밖 직함과 불완전한 괄호는 그대로 남길 수 있다.
- 구분 분류에는 공백을 정리한 값을 쓰지만 purpose에는 원문을 보존한다. NONE의 화면 detail=null 변환은 후속 응답/일정 계층 책임이다.
- 참석자 원문이 목록을 `, `로 연결한 값과 다르면 memo에 원문을 남긴다. 이름이 하나도 남지 않으면 경고다.
- 식별 해시·중복 순번, DB 변경, 일정 생성, 업로드 API와 권한 검증은 KAN-58 이후 범위다. 이 파서는 DB를 호출하지 않는다.

## 검증

`LedgerRowParserTests`에서 날짜 문맥·윤년·월 간 격리·원문 보존·경고와 오류·길이 제한·오류 셀을 검증한다. 가상 워크북을 POI 읽기와 시트 판별부터 파서까지 통과시키는 연결 테스트도 포함한다.

IntelliJ에서 해당 테스트 클래스를 실행하거나 `gradlew.bat test --tests '*LedgerRowParserTests'`로 실행한다. 실제 업로드와 달력 반영 완료를 뜻하지는 않는다.
